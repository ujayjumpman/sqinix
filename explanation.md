# How the Squinix site is built

A walkthrough of the architecture, the tools used, and the reasoning. For the project history and decisions see [context.md](context.md); for run/deploy steps see [README.md](README.md).

## 1. The big idea

The site is a **static website** (plain HTML, CSS, JavaScript and media files) generated by Next.js. There is no server, database or CMS. That makes it:

- runnable from a laptop with no internet (the customer demo),
- uploadable to any web host (the current Apache host, Vercel, Netlify, Cloudflare Pages),
- fast and cheap to run.

The Apple-style "product video that plays as you scroll" is **not a video file**. It is a numbered series of small images (frames). A canvas on the page shows frame N depending on how far you have scrolled. The frames come from 3D scenes we render ourselves.

```
 3D scenes (three.js)  ->  PNG frames  ->  small WebP frames  ->  scroll-scrubbed canvas on the page
 scripts/render/          headless Chrome   scripts/make-sequence   components/motion/ScrollSequence
```

## 4. How the main pieces work

### 4.1 ScrollSequence: the "video that scrubs with scroll"

`components/motion/ScrollSequence.tsx`

1. A tall `<section>` (for example 620 vh) contains a **sticky** full-screen stage with a `<canvas>`.
2. **ScrollTrigger** converts scroll position into progress 0..1, which is smoothed and mapped to a frame number.
3. Frames are fetched after the page has loaded, at low network priority, **coarse first** (frame 0, then every 8th, then the rest) so scrubbing works almost immediately.
4. Memory: the compressed WebP files are kept as blobs (a few MB), but only a window of about 44 frames (28 on phones) around the playhead is decoded into `ImageBitmap`s. The least-recently-needed ones are closed. A 150-frame film never holds hundreds of MB of pixels.
5. Painting uses "cover" fitting and a device-pixel-ratio cap of 2. The painted frame is drawn only when the frame number changes.
6. **Text beats** (headline + sentence) fade/blur in and out at set progress windows. The first beat ships visible in the HTML for a fast first paint.
7. **Fallbacks:** `prefers-reduced-motion` and data-saver visitors get a static layout (poster image plus stacked cards instead of the pinned film). Phones get the lighter portrait frame set.
8. Each section exposes `data-frame`, `data-progress` and `data-loaded` so the automated tests can verify it.

### 4.2 The 3D render pipeline

`scripts/render/`

- `page.html` / `page.js`: an offscreen three.js page (tone mapping, shadows, bloom, environment lighting). It exposes `renderFrame(i, total)`.
- `render.mjs`: starts a tiny local server, launches headless Chrome, loads a scene, and saves one PNG per frame. It runs on the machine's real GPU (about 0.07 s per frame).
- `lib.js`: shared building blocks: materials, rounded boxes, a procedural **fan** (blades, RGB ring), a dark studio stage with a mirror floor, easing helpers, and `shiftView` (slides the image inside the frame to leave room for headlines).
- `gpu.js`: a procedural 3-fan graphics card (shroud, fan blades, fin stack, heat pipes, PCB, backplate, bracket) used by two scenes.
- `scenes/`: one file per film.

| Scene | Used for | What happens |
|---|---|---|
| `rig` | Home | A gaming PC assembles itself (parts fly in, cables draw in, glass panel lowers, RGB lights up), then the camera orbits and pushes in. |
| `gpu` | Gaming | A graphics card separates into layers and reassembles; fans spin. |
| `laptop` | Business | A laptop opens, its screen shows a dashboard, camera pushes into the screen. |
| `servers` | Infrastructure and home | A dolly shot down a data-centre aisle with thousands of blinking LEDs (instanced meshes). |
| `keyboard` | Peripherals | A mechanical keyboard explodes into keycaps, switches, plate, PCB and case with an RGB wave. |
| `hero` | Home hero | A seamless 6-second loop: GPU macro with spinning fans, breathing RGB and drifting dust. Rendered landscape and portrait. |

Everything is made from code: no downloaded models or footage, no brands or logos.

`render-all.mjs` runs the lot: render frames, encode, make cards, encode the hero videos. The render settings (resolution, frame counts) live there. A single scene can be re-rendered with `--only`.

### 4.3 Encoding

- `make-sequence.mjs <frames-dir | video> <name>`: crops/resizes and writes WebP frames plus `manifest.json` and a poster. The **same command accepts a real video file**, so real footage can replace a render later.
- `make-video.mjs`: H.264 MP4 and VP9 WebM (no audio, fast-start), desktop and mobile sizes, plus a poster. MP4 is listed first because it is smaller here.
- `make-cards.mjs`: 3:2 stills (rendered at a chosen moment of each film) for the product showcase, mega menu and related cards.
- `trace-logo.mjs`: traces the PNG logo into an SVG: a silhouette plus blurred luminance layers to rebuild the navy-to-sky gradient, and a flat wordmark path.
- `make-brand-assets.mjs`: favicon, Apple touch icon and the 1200x630 social image.

### 4.4 Smooth scroll and animation plumbing

- `SmoothScroll.tsx` creates Lenis and drives it from `gsap.ticker`; Lenis scroll events call `ScrollTrigger.update`. Anchor links glide; every route change scrolls to the top or to its `#hash`, then refreshes triggers.
- `lib/gsap.ts` registers ScrollTrigger and SplitText once.
- `SplitReveal` splits a headline into lines behind a mask and slides them up. `Reveal` fades/rises content on scroll. `WordHighlight` brightens a sentence word by word. All three respect reduced motion.
- `ProductShowcase` pins the section and moves the track sideways on desktop (`gsap.matchMedia`), and is a native swipe carousel on phones.
- `Preloader` shows the logo mark and a counter, then lifts away (skipped for repeat visits and reduced motion via a tiny inline script that runs before first paint). `template.tsx` runs the curtain between pages; **only opacity is animated on page content**, because a leftover CSS transform would break pinned sections.

### 4.5 Content, forms and contact

- **Quote form** (`QuoteForm.tsx`): name, company, phone, email, interest, quantity/budget, message, plus a hidden honeypot against bots. It validates in the browser. If `NEXT_PUBLIC_FORM_ENDPOINT` is set it POSTs JSON there; otherwise it shows a "demo mode" success state. A **Send via WhatsApp** button builds a pre-filled `wa.me` link and always works. Product pages link into it with `?interest=...&item=...` and it pre-fills.
- Contact data is defined once in `content/site.ts` and used everywhere.
- **No Google Maps embed** (it needed an API key and the internet). The About page uses a styled map card plus an "Open in Google Maps" link.

### 4.6 SEO and sharing

Per-page titles and descriptions, canonical URLs, Open Graph/Twitter image, `ComputerStore` JSON-LD with the address and phone, `sitemap.xml`, `robots.txt`, favicon and touch icons.

## 5. Performance and robustness choices

- **First paint:** hero copy and the first film beat are in the HTML, the preloader overlay covers them, and JavaScript tucks them away only just before the entrance. Result: desktop LCP about 1.0 s.
- **Heavy media is deferred:** the hero video and the film frames start only after the page has loaded and gone idle; frames use low fetch priority; the smaller MP4 is chosen first; phones get lighter files.
- **No layout shift:** images have explicit sizes; CLS is about 0.
- **Offline:** fonts, icons, scripts and media are all local. The smoke test fails if any external request is made.
- **Caching on Apache:** `.htaccess` marks media and fingerprinted assets immutable for a year and HTML as always-revalidate, enables compression, adds basic security headers, redirects the old `*.html` URLs, and sets the 404 page.
- **Prefetch fix:** `scripts/postbuild.mjs` writes flat copies of Next's segment-prefetch files, because a Windows build writes nested folders the client does not request (otherwise every link prefetch 404s).

## 6. Accessibility

Skip-to-content link; real landmarks and a logical heading order; visible focus rings; labelled form fields with error messages; keyboard-reachable carousels; the mobile menu is a labelled dialog; pause control on the hero video; decorative numerals are generated by CSS so they are not read out or contrast-checked; colour contrast checked by axe; full reduced-motion support. Result: zero serious or critical axe violations.

## 8. Swapping in real footage (later)

1. Film the products (see [SHOT-LIST.md](SHOT-LIST.md)).
2. `node scripts/make-sequence.mjs clip.mp4 gpu --frames 120` (and `--variant mobile` with a portrait clip).
3. `node scripts/make-video.mjs hero.mp4 hero` for the hero loop.
4. `node scripts/make-cards.mjs --from-seq` for the card stills.
5. If the new footage tells its story at different moments, adjust the text beats' `from`/`to` in `app/page.tsx` and `app/products/[line]/page.tsx`.

No component code changes are needed.

## 9. Known limits and next steps

- The range cards are indicative placeholders (no prices, no brands) until the client supplies their real lineup.
- The quote form needs a form-service endpoint before launch (see README).
- The logo is a traced PNG; replace `public/brand/*` with the original vector.
- Copy contains claims about process quality that the client must confirm (CONTENT-CHECKLIST.md).
- Lighthouse's simulated slow-mobile profile scores the home page 78 (product page 85); real throttled loads are much faster, but trimming JavaScript further would help that simulation.
- Not built from the original plan: a spec comparison table on product pages and a shrink-to-card media effect.
- Dev server note: `npm run dev` must be opened via `localhost`, not `127.0.0.1`, or Next's hot-reload socket errors (harmless).
